# FPGA开发技能包 (Skill Pack)

## 1. 适用场景
在 FPGA 开发中，上位机（如 Python/PyQt）需要向 FPGA 下发多参数指令（如频率、波形选择）或大块波形数据。本 Skill 提炼了一套基于纯 Verilog 状态机（参考 `cmd_parser.v`）和双口 RAM 写入（参考 `awg.v`）的高可靠通信协议与代码骨架。可直接复用于电机控制、图像传输等任何需要 PC 与 FPGA 动态交互的场景。

## 2. 核心设计范式
### 2.1 轻量化协议定义
*   **下行指令（PC -> FPGA）**：采用 ASCII 明文，以 `\n` (0x0A) 结尾。
    *   `W0`~`W3`：切换波形（正弦、方波、三角、锯齿）。
    *   `F`+`频率字控制字`：设置频率（直接下发 FTW 32位数值）。
    *   `U512,2048`：向 RAM 的 512 地址写入数据 2048。
*   **上行数据（FPGA -> PC）**：采用二进制数据帧，格式为 `[0xAA] [低8位] [高4位] [0x55]`。
    *   **设计精髓**：FPGA 产生 12 位波形数据，拆分为低 8 位和高 4 位（高 4 位补零凑 8 位）分两包发送。加入帧头 `0xAA` 和帧尾 `0x55` 用于数据对齐，彻底杜绝 UART 粘包与错位。


### 2.2 状态机容错解析
参考 `cmd_parser.v`，在 `S_IDLE` 状态下识别首字符并跳转。
* **关键点**：在状态机中遇到非法字符直接 `default: state <= S_IDLE;` 兜底，防止死锁。代码不要只有 `if (Rx_Done)` 组合逻辑，实测会导致 `ftw` 数据在切换时出现毛刺，必须加入 `ftw_valid` 单周期脉冲进行非阻塞赋值锁存。

### 2.3 双口 RAM 读写分离
对于手绘波形等大块数据，例化双口 RAM。Port A 接串口解析的写使能（`awg_wr_en`）和写地址；Port B 接 DDS 独立的相位累加器读地址，实现无冲突的实时波形输出。

### 2.4 上位机频率控制字计算
计算机端输入频率 `f_out` 后，直接计算 `FTW = f_out * 2^32 / f_clk`（注意使用 64 位整数避免溢出），FPGA 端无需做任何除法运算。

## 3. UART 串口通信避坑指南
* **协议结尾匹配**：上位机（Windows/Linux）串口助手在勾选“发送新行”时，默认发送 `\r\n` (0x0D, 0x0A)，而不仅仅是 `\n`。FPGA 状态机解析时，必须同时兼容这两种字符，否则命令会卡死。
* **情况说明**：在用串口助手进行早期板级测试时，我们发现指令毫无反应，排查发现 Windows 系统下的串口调试助手在勾选“发送新行”时，默认发送的是 `\r\n` (0x0D, 0x0A)，而初版状态机只认 `\n`，FPGA 收到 `\r` 时会直接触发状态机的 `default` 分支复位，导致后续的 `\n` 永远等不到，系统卡死。为了解决这个问题，我们在 `cmd_parser.v` 的每个解析状态中，增加了对 `\r` (0x0D) 的忽略过滤，并严格保留了 `default: state <= S_IDLE;` 兜底分支，极大提高了状态机面对噪声和非法字符的鲁棒性。但在团队自行编写的 Python 上位机中，我们严格约定了通信协议，将发送尾部强制设置为 `\n`（`FRAME_TAIL = "\n"`），从源头避免了冗余字符。也就是说这个逻辑只在串口调试的时候发挥作用，在后期可以直接用上位机测试而不再使用串口调试工具时这个逻辑不再起作用。   
* **波特率与采样率平衡**：对于需要实时回传波形的系统，115200 波特率会导致上位机画面严重卡顿（采样率仅 2.5kHz）。推荐提升至 `921600`，并在 Python 端使用多线程读取，防止阻塞 UI。
* **缓冲区溢出防范**：当 FPGA 高速发送数据时，Python `serial.Serial` 的 `in_waiting` 会迅速积压。读取时必须限制单次读取字节数（如 `min(n, 256)`），否则会导致 GUI 卡死。

## 4. Vivado 常见报错处理
* **IP 缓存不更新**：修改了 COE 文件或重新生成 IP 后，仿真波形依旧没变。解决方法：关闭 Vivado -> 删除工程目录下的 `.sim` 文件夹 -> 重新打开并运行仿真。
* **ILA 无法生成或丢失 .ltx 文件**：在存在时序违例或 DRC 错误时，Vivado 会拒绝生成 `.ltx`。解决方法：修复违例，或删除 `impl_1` 文件夹重新跑实现。
* **时序违例 (WNS 为负) 的快速处理**：若违例路径集中在调试接口 (ILA) 或异步输入 (UART)，可通过 XDC 添加 `set_false_path` 忽略这些路径，或增加一级寄存器打拍处理。


## 5. 已验证的效果与边界
*   **通信吞吐**：在 921600 bps 波特率下，单次下发 4 字节控制指令耗时约 45 us。
*   **大块数据下发**：手绘 AWG 模式全量下发 1024 个点（含上位机 2ms 间隔延时），总耗时约 2 秒。
